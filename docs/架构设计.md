# 智能售后 Agent 架构设计

## 目标与请求流程

面向合成订单、物流、商品和政策，提供可追溯问答、只读查询、缺参澄清与确认建单。应用分为 Agent API、冻结 Mock、自建 pgvector 三服务；容器与 pgvector 正向验收尚未完成。

FastAPI 校验身份，服务端 Principal 决定归属，模型不能自行指定用户。Controller 管理会话、消息去重、恢复版本与并发；LangGraph 负责目标理解、逐步动作和中断恢复。模型只提出候选，经确定性守卫、参数来源与覆盖校验后执行。读取同一对象的订单后才能查物流。

## 数据与知识

| 内容 | 部署入口 | 一致性约束 |
|---|---|---|
| 政策 | `knowledge/*.md`、`ingest.py` | 30 篇、5 个旧版本；API 与 CLI 校验文件集合和 SHA-256 |
| SQL | `database/schema.sql`、`ecommerce.db`、`dictionary.json` | 启动核验三份摘要，拒绝 WAL/SHM/journal；只读连接 |
| 评测 | `eval/golden_dataset.jsonl` | 基线运行器和评分器默认入口；缺失或摘要变更提前拒绝 |
| 原基线 | `data/c004-r01/baseline/` | Mock、Oracle 与 SnapshotVerifier 必需的完整冻结参考包 |
| 运行库 | 私有 `runtime/`，容器独立卷 | 不写入部署种子目录或冻结包，不进入仓库 |

RAG 先用 embedding 发现主题，再按日期、适用条件与版本关系裁决政策，返回文档名、段落和锚点。pgvector 是默认后端；memory 必须显式选择，每次进程启动建索引，不会静默降级。

Text-to-SQL 使用 sqlglot、允许表/字段、可信身份视图、SQLite authorizer、资源限制和只读连接。支持受约束 Join，缺少商品订单明细时不编造关联。错误后重新生成仍需重新校验。金额取实际执行结果，整数分转换为人民币元展示。

## 写入与恢复

写工单前绑定订单与原因并等待确认，恢复必须携带当前 session、interrupt 和 revision。旧恢复拒绝，同消息精确重放不重复消费确认。运行账本、确认消费和发送占位位于同一 runtime SQLite 事务；checkpoint 独立，不承诺跨库原子性。恢复时核对账本，无法证明可继续则保守终止。

读取 429/500 有界重试，考虑退避、Retry-After 与预算。持续失败时说明原因，符合条件才提议人工核查建单；明确只读时不追加写操作。写后不确定保持 UNKNOWN 和占位，不盲目重发。Mock 没有远端幂等或结果反查，因此不承诺业务 Exactly-Once。

## 协议与观测

`/chat` SSE 包含公开执行说明、工具开始/核验结果/错误、中断、回答和 done。最终答案当前整段发送，公开说明不包含内部推理，断连不保证交付终帧。私有 Trace 记录脱敏模型请求/候选、SQL、政策片段、HTTP、耗时与 token，通过关联 ID 与公开响应对照。

live 只证明进程可应答；ready 检查控制器、身份、业务快照与索引，配置有效不等于模型服务实时可用。

## 部署与验收

`docker/docker-compose.yml` 以仓库根目录为 build context，引用 `docker/Dockerfile`；环境文件与基线挂载指向上一级，Agent runtime、Mock 工单与向量库使用独立卷。流程和离线准备见[部署手册](部署手册.md)。

回归、受控真实 HTTP、真实模型与独立语义需分别验收。当前证据见[验证记录](reports/交付验证记录.md)、[评测报告](../eval/报告.md)，缺口见[需求追踪](需求追踪矩阵.md)与[风险清单](风险与待确认事项.md)。
